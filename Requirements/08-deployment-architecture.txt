# FixHome - Deployment Architecture

## Version

**Version:** 1.0

**Status:** Draft

---

# 1. Overview

This document describes the deployment architecture of the FixHome platform.

The architecture supports:

* local development
* testing environment
* production deployment

The initial deployment approach follows a simple and scalable architecture.

---

# 2. Deployment Goals

The deployment architecture should provide:

* Easy development setup
* Reliable application execution
* Secure configuration management
* Database persistence
* Ability to scale individual components
* Simple maintenance

---

# 4. Application Components

## Backend Service

Technology:

```text
Java 21
Spring Boot 3
```

Deployment:

```text
Docker Container
```

Responsibilities:

* REST API
* Authentication
* Business logic
* Database communication

---

## Database

Technology:

```text
PostgreSQL
```

Responsibilities:

* Store application data
* Maintain relationships
* Transaction management

Stored data:

* Users
* Profiles
* Requests
* Offers
* Reviews

---

## Cache Layer

Technology:

```text
Redis
```

Initial usage:

* Session related data (future)
* Frequently requested data
* Rate limiting

Possible future usage:

* Real-time features
* Notifications
* Chat support

---

## File Storage

Technology:

```text
Cloudflare R2
or
Amazon S3
```

Purpose:

Store:

* Request images
* Profile images
* Documents (future)

Database stores only:

```text
image_url
```

not binary files.

# 5. Environment Architecture

The system should have separate environments.

---

# Development Environment

Purpose:

Local development.

Components:

```text
Spring Boot

PostgreSQL Docker Container

Redis Docker Container

Local Storage
```

---

# Testing Environment

Purpose:

Automated testing.

Components:

```text
Backend Application

Test Database

CI Pipeline
```

---

# Production Environment

Purpose:

Real users.

Components:

```text
Backend Server

PostgreSQL Database

Redis

Object Storage

Monitoring
```

---

# 6. Docker Architecture

The project should provide:

```text
docker-compose.yml
```

for local development.

Example:

```text
fixhome

|
+-- backend
|
+-- database
|
+-- redis
|
+-- docker-compose.yml
```

---

Development startup:

```bash
docker compose up
```

should start:

* PostgreSQL
* Redis
* Backend dependencies

---

# 7. Configuration Management

Sensitive configuration must never be stored in source code.

Examples:

Database:

```text
DB_USERNAME
DB_PASSWORD
DB_URL
```

JWT:

```text
JWT_SECRET
JWT_EXPIRATION
```

Storage:

```text
R2_ACCESS_KEY
R2_SECRET_KEY
```

Firebase:

```text
FCM_KEY
```

# 10. Database Migration

Database changes are managed using:

```text
Flyway
```

Deployment flow:

```text
Application Start

        |

Flyway executes migrations

        |

Database updated

        |

Application starts
```

# 13. Backup Strategy

Database:

* Regular PostgreSQL backups

Images:

* Object storage versioning

Important data:

* User accounts
* Service history
* Reviews

---

# 14. Scalability Strategy

Initial architecture:

```text
Single Spring Boot instance
+
Single PostgreSQL database
```

Future scaling:

```text
Load Balancer

        |

Multiple Backend Instances

        |

Shared PostgreSQL

        |

Redis Cluster
```

---

# 15. Security Deployment Rules

Production must use:

* HTTPS
* Secure environment variables
* Database access restrictions
* Firewall rules
* Regular dependency updates

---

# 16. Deployment Principles

The FixHome deployment strategy follows:

* Infrastructure simplicity
* Automation
* Security
* Observability
* Incremental scaling

The system should grow only when business requirements require additional complexity.
