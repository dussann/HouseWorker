# FixHome - REST API Specification

## Version

**Version:** 1.0

**Status:** Draft

---

# 1. API Overview

FixHome backend exposes a REST API used by:

* React Native mobile application
* React Admin panel
* Future integrations

Communication format:

```text
HTTP + JSON
```

Base URL:

```text
/api/v1
```

Example:

```text
GET /api/v1/service-requests
```

---

# 2. Authentication

Authentication mechanism:

```text
JWT Bearer Token
```

Request example:

```http
Authorization: Bearer {jwt_token}
```

Public endpoints:

```text
POST /auth/register

POST /auth/login
```

Protected endpoints require authentication.

---

# 3. API Response Standard

Successful response:

```json
{
  "data": {},
  "message": "Success"
}
```

Error response:

```json
{
  "timestamp": "2026-08-02T20:00:00",
  "status": 400,
  "error": "Validation failed",
  "path": "/api/v1/service-requests"
}
```

---

# 4. Authentication API

## Register User

### POST

```
/auth/register
```

Request:

```json
{
  "email": "user@test.com",
  "password": "password123",
  "phone": "+38160000000",
  "role": "CUSTOMER"
}
```

Response:

```json
{
  "id": 1,
  "email": "user@test.com",
  "role": "CUSTOMER"
}
```

---

## Login

### POST

```
/auth/login
```

Request:

```json
{
  "email": "user@test.com",
  "password": "password123"
}
```

Response:

```json
{
  "accessToken": "jwt-token",
  "refreshToken": "refresh-token"
}
```

# 9. Service Request API

## Create Service Request

### POST

```
/service-requests
```

Customer only.

Request:

```json
{
 "categoryId":2,
 "description":"Water leaking from boiler",
 "imageUrl":"image.jpg",
 "latitude":44.7866,
 "longitude":20.4489
}
```

Response:

```json
{
 "id":10,
 "status":"NEW"
}
```

---

## Get Customer Requests

### GET

```
/service-requests/my
```

---

## Get Request Details

### GET

```
/service-requests/{id}
```

---

## Change Request Status

### PATCH

```
/service-requests/{id}/status
```

Request:

```json
{
 "status":"IN_PROGRESS"
}
```

---

# 10. Offer API

## Create Offer

### POST

```
/offers
```

Craftsman only.

Request:

```json
{
 "requestId":10,
 "price":30,
 "message":"I can come today at 18:00"
}
```

---

## Get Offers For Request

### GET

```
/service-requests/{id}/offers
```

---

## Accept Offer

### PATCH

```
/offers/{id}/accept
```

Business rules:

* Only customer can accept.
* Only one offer can be accepted.
* Other offers become rejected.

---

# 11. Review API

## Create Review

### POST

```
/reviews
```

Request:

```json
{
 "requestId":10,
 "rating":5,
 "comment":"Excellent service"
}
```

Rules:

* Request must be COMPLETED.
* Only customer can review.

---

## Get Craftsman Reviews

### GET

```
/craftsmen/{id}/reviews
```

# 14. API Security Rules

## Customer

Can:

* manage own profile
* create requests
* view own requests
* accept offers
* create reviews

---

## Craftsman

Can:

* manage own profile
* view matching requests
* create offers
* manage accepted jobs

---

## Admin

Can:

* manage users
* verify craftsmen
* manage categories

---

# 15. API Design Principles

The API follows:

* REST principles
* Resource-oriented URLs
* Stateless communication
* DTO based responses
* Validation on backend
* Consistent error handling
