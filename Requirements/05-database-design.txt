# FixHome - Database Design

## Version

**Version:** 1.0

**Status:** Draft

---

# 1. Database Overview

FixHome uses PostgreSQL as the primary relational database.

The database is designed around the marketplace domain:

* users
* customers
* craftsmen
* service requests
* offers
* reviews

The database follows a normalized relational model with clear foreign key relationships.

---

Database:

```text
PostgreSQL
```

ORM:

```text
Spring Data JPA + Hibernate
```

Migration tool:

```text
Flyway
```

Caching layer:

```text
Redis (future optimization)
```

# 3. Naming Conventions

Database conventions:

* Table names: snake_case
* Column names: snake_case
* Primary keys: id
* Foreign keys: entity_id

Examples:

```text
service_requests

customer_id

created_at
```

# 5. User Table

## users

Stores authentication and authorization information.

Structure:

| Column     | Type         | Description   |
| ---------- | ------------ | ------------- |
| id         | BIGSERIAL    | Primary key   |
| email      | VARCHAR(255) | Unique email  |
| password   | VARCHAR(255) | BCrypt hash   |
| phone      | VARCHAR(50)  | Phone number  |
| role       | VARCHAR(50)  | User role     |
| created_at | TIMESTAMP    | Creation time |
| updated_at | TIMESTAMP    | Update time   |

Roles:

```text
CUSTOMER
CRAFTSMAN
ADMIN
```

Constraints:

* email must be unique
* password cannot be null
* role cannot be null

---

# 6. Customer Profile Table

## customer_profiles

Stores customer-specific information.

Structure:

| Column     | Type         |
| ---------- | ------------ |
| id         | BIGSERIAL    |
| user_id    | BIGINT       |
| first_name | VARCHAR(100) |
| last_name  | VARCHAR(100) |
| address    | VARCHAR(255) |
| latitude   | DECIMAL      |
| longitude  | DECIMAL      |
| created_at | TIMESTAMP    |
| updated_at | TIMESTAMP    |

Relationship:

```text
users
 |
 |
customer_profiles
```

Constraint:

```text
One User -> One CustomerProfile
```

# 9. Craftsman Categories Table

## craftsman_categories

Many-to-many relationship.

Purpose:

Structure:

| Column       | Type      |
| ------------ | --------- |
| id           | BIGSERIAL |
| craftsman_id | BIGINT    |
| category_id  | BIGINT    |

Example:

```text

    + Electrician

```

# 17. Database Design Principles

The database should:

* protect data integrity
* enforce relationships
* support future growth
* remain simple for MVP
* avoid premature complexity

The first version should prioritize correctness and maintainability over optimization.
